# Designer trial — 10–15 minutes

This is a plan, not evidence that a trial happened. No participants or results have been collected yet.

## Who to invite

One independent designer who has actually negotiated scope or price in customer messages. The participant should volunteer; no outreach has been sent by the assistant.

## Privacy and setup

Use authored examples first. Do not ask for customer names, email addresses, payment details, confidential contracts, or full chat histories. If the participant wants to use a real scenario, obtain permission and have them rewrite it without identifying details. Explain that analysis uses an external model and its retention policy has not been verified. No real payment is necessary for this trial.

## Tasks

1. Before using the tool, ask the participant to describe how they normally reconstruct an agreed scope and amount. Record their own account, not a suggested pain point.
2. Let them inspect the example with an accepted logo quote and an unanswered poster request. Ask them to find the current agreed service and the unresolved request.
3. Let them analyze the revised-price example. Ask what they think is preventing invoice creation and what they would do next.
4. Ask them to add or edit a message and explain whether they expect the previous confirmation to remain valid.
5. Show the explicitly labeled, previously verified sandbox invoice. Ask them to distinguish draft, sent, and paid. Do not request another payment.

If the model fails or times out, record that event rather than swapping in an undisclosed saved answer. The participant may stop at any time.

## Neutral follow-up questions

- In your own work, how often do you have to reconstruct an agreement from messages?
- Which extracted detail would you check first, and why?
- Which part, if any, was confusing or unnecessary?
- Would this replace any step you currently perform? If so, which step?
- What would need to change before you would trust a draft enough to review and send it?
